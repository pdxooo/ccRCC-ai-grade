# 高分辨率第 1 阶段：训练与分析（highres_stage1_train_v1_20261021）

本目录实现 `takeover_20261021/高分辨率小样本试验方案_草案_20261021.md`（下称"方案"）第 5、6、7.6、11 节。**代码和本文件在看到任何第 1 阶段成绩之前锁定**（`LOCK.json`）。锁定后任何改动都必须作为新版本记录，并且只能发生在看到第 1 阶段成绩之前。

| 项目 | 内容 |

| 标签 | 韩国公开临床表的 ISUP（经 patient_manifest.csv）。y = ISUP − 1：G1→0，G2→1。锁定表、manifest、五折表三处必须一致，否则拒绝运行 |

## 2. 训练（每次运行 = 编码器 × 臂 × 种子 × 折）

| 项目 | 锁定值 |
|---|---|
| 编码器 | UNI（1024 维）、Virchow2（2560 维），冻结特征 |
| 臂 | **L**、**H**、**Hd**（即 H↓）为决策臂；**Lfull**（全片 L 特征）为参照臂，只用于量化抽样损失，不进入决策 |
| 模型 | gated ABMIL：每个实例 L2 归一化 → 线性 256 + ReLU + dropout 0.25 → 门控注意力 128 → 线性 2 类。与既往 4 级模型同构，只把输出改为 2 类 |
| 实例 | L 与 Lfull：一个位置（图块）= 一个实例。H 与 Hd：一个 64 μm 子块 = 一个实例，每个位置 4 个 |
| 每轮抽样 | 每例抽 512 个位置（不足全取，不放回，排序）；L 用这 512 个特征，H/Hd 用这 512 个位置的全部 4 个子块（2,048 个实例）。**同一种子、折、轮、病例下，L/H/Hd 和两个编码器抽到完全相同的位置**。Lfull 从该例全部图块中按同一规则抽 512 个 |
| 轮数 | 固定 40 轮，取第 40 轮结束时的模型，不早停、不选模 |
| 优化 | AdamW，lr 1e-4，weight decay 1e-4；每 4 例累积一次梯度；梯度裁剪 5；交叉熵 × 类别权重 n/(2·该类例数)（每折 48/48，权重均为 1） |
| 训练顺序 | 每轮按固定种子打乱 96 例的顺序，各臂、各编码器相同 |
| 种子 | 3 个（索引 0、1、2）。模型初始化种子 = 20261022 + 100 × 种子索引 + 折；抽样与顺序由 (20261022, 种子索引, 折, 轮, 病例) 的 sha256 派生。两个编码器、所有臂共用 |
| 测试 | 该例全部位置（L/Lfull：全部特征；H/Hd：全部子块），整例统一计算注意力（分块编码、全局 softmax），输出 P(G2) |
| 平台 | lab-a6000 的 RTX A6000，torch 确定性算法、关闭 TF32。全部运行必须在同一平台；断点续跑只允许同平台 |
| 运行数 | 决策臂 2 × 3 × 3 种子 × 5 折 = 90；参照臂 2 × 1 × 3 × 5 = 30；共 120 |

训练过程只记录训练损失，**不计算、不打印任何测试成绩**。测试预测写入每次运行的 `predictions.json`，只由 `evaluate.py` 在 120 次运行全部完成后统一分析。

## 4. 协议 7.6 训练检查（check76.py；不看任何成绩）

- **病例（事先规定）：** 按 `stage1_cases.txt` 的顺序取前 4 个 G1 和前 4 个 G2（即第 0 折的前 4 + 4 例），共 8 例。第 0 阶段只有 4 例，所以用第 1 阶段的病例（用户 2026-10-21 同意）。
- **内容：** 对 2 个编码器 × 4 个臂（L、H、Hd、Lfull）各做：
  1. 用正式配方（512 个位置、分块 4096）在这 8 例上训练 2 轮，不中断；
  2. 同样训练，第 1 轮后暂停（退出 75），在**新进程**里续跑第 2 轮；有两张卡可见时续跑放在另一张卡上；
  3. 两者的模型参数、优化器状态、随机数状态、训练历史和预测必须**逐位相同**；
  4. 用三种分块（4096、整包一次、333）计算这 8 例的 P(G2)，最大绝对差 ≤ 1e-5（分块与整包一致）；
  5. 标签映射：120 例在锁定表、manifest、五折表中的 ISUP 与折号一致；y 只取 0/1；每折训练集 48/48、测试集 12/12；训练集与测试集不相交；120 例各被测试一次；检查运行中实际使用的标签与锁定表一致。
- **不计算任何成绩：** 预测只用于两条腿之间、不同分块之间的比较，不与标签比较，不输出 AUC、准确率或损失以外的任何数字。
- **输出：** `CHECK76_PASS.json`（PASS/FAIL、代码签名、平台、每项检查结果）。FAIL 时不得开始第 1 阶段训练。只有比较不一致（或某条腿退出 1/2）才记为 FAIL；某条腿被杀（如 OOM）、超时、遇到暂时性 GPU/内存问题或收到停止信号时什么都不记录，退出 74/75，之后重跑。

## 5. 分析（evaluate.py，120 次运行全部完成后运行一次）

前提：120 份回执齐全、哈希一致；全部属于同一代码签名、同一平台、同一锁定病例表；每个编码器 × 臂 × 种子的 OOF 恰好覆盖 120 例各一次。

- **AUC：** G1 对 G2，以 P(G2) 为分数的 Mann-Whitney AUC（并列计 0.5）。
- **主要指标：** 每个编码器 × 臂，先把 3 个种子的 P(G2) 按病例平均，再在 120 例合并 OOF 上算 AUC。Δ(H−L) = AUC(H) − AUC(L)。
- **95% 区间：** 按病例 bootstrap，2,000 次，**在 G1、G2 内分别有放回抽样**（保持 60/60，避免出现单一类别），百分位区间；同一次抽样同时用于各臂，所以 Δ 是配对的。随机种子 20261021。
- **次要指标：** Δ(H−Hd) 及其区间；每个种子各自的 Δ(H−L)（该种子的 120 例 OOF）；以 0.5 为界的 G2 召回率和 G1 召回率；此前被 6 个病理编码器全部判错的 ISUP 2 病例（`inputs/prior_all_wrong_isup2_v1.json`，由 `make_prior_errors.py` 从首轮 OOF 预测重建，共 46 例，第 1 阶段样本中 22 例）里，各臂判为 G2（P ≥ 0.5）的例数；其中被 6 个编码器全部判为 G1 的子集（第 1 阶段样本中 14 例，真正的 G1/G2 混淆）单独报告；参照臂 Lfull 的 AUC 与 Δ(L−Lfull)（抽样损失）。

## 6. 决策规则（方案第 6、11 节；本节的具体化在锁定前写定）

对每个编码器 e，用决策臂的数字计算：

- d = AUC_avg(H) − AUC_avg(L)（3 个种子概率平均后的 AUC 差）
- d_s = AUC_s(H) − AUC_s(L)，s = 0, 1, 2（每个种子各自的 AUC 差）
- h = AUC_avg(H) − AUC_avg(Hd)

判定：

| 结果 | 条件 |
|---|---|
| **进入第 2 阶段** | 至少一个编码器同时满足：d ≥ 0.03；三个 d_s 都 > 0；h > 0 |
| **阴性，止损** | 不满足上一行，且**两个编码器都**满足：d < 0.03，并且（d ≤ 0 或三个 d_s 方向不一致，即既有 > 0 又有 ≤ 0） |
| **不明确，由用户决定** | 其他情况 |

具体化说明（方案原文未写明，这里事先固定）：

1. "3 个种子都 > 0"指每个种子各自的 120 例 OOF 上 AUC(H) − AUC(L) 严格大于 0。
2. "H 胜过 H↓"指 3 个种子平均后的 AUC(H) 严格大于 AUC(Hd)，只看点估计，不要求区间不含 0。
3. "阈值 +0.03"比较的是点估计，不是区间下限。
4. 方案中"两个编码器的 Δ(H−L) 都 ≤ 0，或各种子方向不一致"理解为：两个编码器各自都属于"d ≤ 0 或种子方向不一致"。若只有一个编码器如此，另一个为正但未达进入标准，判为不明确。**用户 2026-10-21 决定：平均增益 d ≥ 0.03 的编码器不算阴性**（即使有一个种子 ≤ 0），以免一个有噪声的种子终止一个有希望的方向；这种情况判为不明确。
5. 参照臂 Lfull 不参与判定。区间只作报告，不参与判定（120 例时区间约 ±0.06，第 1 阶段只看方向）。

结果写入 `RESULTS.json` 和 `RESULTS.md`，原样报告，阴性也报告。不得据此修改标签、病例、位置、阈值或成员。
